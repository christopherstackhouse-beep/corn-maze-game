# Codex project guidance: Lester After Dark

## Purpose and source of truth
This repository is the playable browser game **Lester After Dark**, presented as **North Fulck Farms presents Amazing Fall Fun Time**. Preserve the functioning game and its intentionally strange horror-comedy tone. The checked-in source code is the ultimate reference for implemented mechanics. This file records established design decisions and engineering guardrails; do not replace tested behavior with guesses.

## Non-negotiable gameplay and narrative requirements
- Keep the existing fixed, repeatable 21×21 corn maze layout and first-person browser play. Preserve keyboard/mouse controls, flashlight, net launcher, minimap, audiovisual atmosphere and existing animations.
- There are **22 visually diverse ordinary guests** and **one hidden alien visitor**. Do not reveal the alien's identity upfront.
- **Guest Goodwill** starts at 100. Giving a map to an ordinary guest restores **3** goodwill. Helping the alien with a map restores goodwill to **100** and triggers its cinematic tractor-beam extraction. These outcomes are distinct.
- Lester's interaction with ordinary guests can drain **5 goodwill every 3 seconds per guest**, capped at **15** for the associated drain mechanic. Netting an innocent ordinary guest costs **25 goodwill** and counts toward guest complaints.
- At **three guest complaints**, the guests become hostile and an unavoidable chase/loss sequence follows. Keep the actual consequence in gameplay but **do not spoil it on the main menu**.
- Lester's first encounter is an impossibly fast escape with the line **“Hehehe you’ll never catch me!”**. On the later charging encounter he says **“Ohhh someone looks ticklish! I’m gonna get you!”**. Preserve the encounter progression, recorded dialogue when available, tickle penalties, and distinct capture/loss cinematics.
- Netting the alien makes it angry and triggers the hostile pursuit and incineration sequence, including the existing film/video. Giving it a map instead triggers the nonviolent extraction. Maintain alien walking/appearance from front, back, left and right, and refine rather than replace the existing animations.
- Preserve the Lester capture sequence (including the crying Lester sprite), defeat performance, audio, guest interactions, and all existing assets. Do not silently substitute placeholder graphics, autogenerated assets, or browser speech for recorded audio.
- Keep suspense in the player-facing introduction: the approved warning is **“Netting an innocent visitor costs 25 Guest Goodwill and can lead to dire consequences.”** Do **not** disclose that guests turn against the player or add **“Run while you can.”** Retain the minimap hint, including that Lester's location flashes every **30 seconds**.
- Maintain the version text introduced in Version 1.1 on the main menu unless a later user request changes it.

## Controls and feel
WASD moves, mouse looks/fires, right click gives maps, Shift sprints, R reloads, F flashlight, M toggles minimap, and Escape pauses. Preserve existing behavior, targeting, sound, raycast rendering, and keyboard/pointer-lock handling. Avoid adding explanatory main-menu copy that removes the game's mystery.

## Mobile input prototype (Phase 1)
- Landscape touch controls are an additive input adapter in `dist/touch-controls.js`, with a provisional safe-area layout in `dist/touch-controls.css`. Preserve the desktop keyboard/mouse path.
- Keep independent Pointer Event IDs/capture for joystick, horizontal look, held sprint, and intentional action taps. Reuse existing movement/collision and action functions; never duplicate gameplay/scoring rules in the touch interface.
- Touch play must not require pointer lock or orientation-lock APIs. Portrait play pauses behind a rotation prompt and requires an explicit resume after rotation. Clear held inputs on pause, focus/visibility loss, cancellation, orientation changes, and cinematics.
- Hide/reset the gameplay touch overlay during menus, leaderboards and cinematics. Preserve all existing media and the backend contract. This is a prototype; real iOS Safari and Android Chrome acceptance testing is still required. See `docs/MOBILE-CONTROLS.md` for controls, tests and the next-phase checklist.
- Audio activation must be requested directly from start/resume gestures, reuse the existing context/graph, and preserve intentional mute. Check context state and offer TAP TO ENABLE SOUND when activation fails; physical-device audio acceptance remains separate from automated tests.

## Project organization
- `dist/` is intentionally tracked and contains the runtime HTML, CSS, JavaScript, sprites, music, dialogue, and cinematic media. The site is not a conventional bundled SPA.
- `dist/game.js` hosts main gameplay/raycast logic; `dist/guests.js` guest behavior; `dist/lester-ai.js` encounter progression; `dist/alien.js` alien behavior/animations; `dist/capture.js` and `dist/defeat.js` major cinematics; `dist/leaderboard.js` browser scoreboard.
- `api/`, `server/`, and `migrations/` implement the Vercel leaderboard and persistent database. `scripts/build-vercel.mjs` performs build checks/migrations. `vercel.json` configures production deployment.
- Read `README.md`, `package.json`, `vercel.json`, and relevant tests before changing infrastructure. Keep `dist/leaderboard-config.js` using the same-origin API; do not hardcode credentials or an external API origin into browser assets.
- The original Cloudflare adapter and documentation remain optional; production hosting is GitHub → Vercel.

## Shared leaderboard contract
- The leaderboard uses same-origin API endpoints: `POST /api/runs`, `POST /api/scores`, and `GET /api/leaderboard`; an authenticated cleanup cron uses `/api/cleanup`.
- Players enter a public arcade name without creating an account. Preserve the current privacy notice and server-side input checks.
- Rank by **fastest successful capture time**, then **higher remaining Guest Goodwill**; server ordering further stabilizes ties. Top 25 are shown. Scores must survive redeployments and restarts.
- Production storage is a persistent remote **Turso/libSQL** database. Server-only Vercel variables: `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `RATE_LIMIT_SALT`, and `CRON_SECRET`. Never commit real values, copy them into frontend code, expose them in PR comments, or log tokens.
- Existing migrations are checksummed and applied by the Vercel build when the database is configured. Do not modify already-applied migrations, delete production scores, weaken submission validation/rate limiting, or silently reset the database. For schema changes, add new forward migrations and test against a disposable database.
- Prefer separate preview/staging and production databases so test scores never pollute live rankings. Do not point an experimental deployment at production without explicit approval.

## Safe coding and deployment workflow
1. Start from the latest `main`. Understand affected systems before changing them.
2. Work on a feature branch. Make small, focused changes; preserve unrelated gameplay and media.
3. Run `npm ci`, `npm test`, and `npm run build` with Node.js 24. Existing baseline has nine automated tests. Report failures honestly; passing unit tests do not replace a browser gameplay test.
4. Inspect changes and test interaction flows when possible: loading/start, ordinary guest net/map, Lester's encounters and capture, complaints/hostile chase, alien net vs. map cinematics, audio, minimap, leaderboard creation and submission, and mobile warning.
5. Propose a pull request against `main` and allow Vercel to create a preview. Verify visible changes in the **branch preview**, not the production URL. Do not merge or push to production without user approval.
6. After approval, merge and verify Vercel production deployment and a browser smoke test. If you cannot create the PR because an environment blocks GitHub's API, report the branch name and comparison link instead; do not imply it was merged.
7. For changes involving databases, secrets, migrations, APIs, access policies, or scheduled cleanup, explain the operational implications and require explicit approval before modifying production data/settings.
